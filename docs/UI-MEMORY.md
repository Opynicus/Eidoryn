# UI 内存测量与优化

本次先测量 SVG、字体/文本和布局/元素，再消除重复工作。数据来自内置原创演示，不加载 BIOS、光盘或文件记忆卡；不能据此推算游戏帧率。

## 测量口径

- **存活堆内存**：gperftools 记录的已分配、尚未释放的请求字节数，是采样时刻的值，不是峰值，也不是 RSS。
- **累计分配率**：两个预热后的堆快照之差除以实际转储间隔，包括已经释放的临时对象。它反映分配压力，不代表内存泄漏。
- **字体文件映射**：另外读取 Linux `smaps`，分别统计字体文件的映射大小、RSS 和 PSS。映射了一个完整 CJK 字体文件不等于所有页面都驻留。
- **进程 RSS**：另启一组不注入分析器、使用默认分配器的进程测量。不能拿注入 tcmalloc 后的 RSS 与默认分配器混比。

调用栈分类互斥：SVG 解析/栅格化；字体数据库、字形与文本排版；Taffy 布局与 GPUI 元素；共享图集/场景缓冲；其他。图集和场景缓冲可能由第一个字形或图标触发扩容，单独列出，避免将共享资源全归给 SVG 或字体。GPU 显存没有按这三类拆分，不能把下面的 CPU 堆数据当作完整图形内存。

统计依赖可解析的原始可执行文件及本机共享库，优化编译的内联、相同函数合并和调用栈深度限制会影响细粒度归因。脚本核对每条分配与总数、ELF 装载偏移，以及采集时的二进制 SHA-256；原始快照和系统路径只保存在指定的本地输出目录。

## 测量结果

2026-11-12，AMD Ryzen 9 8945H、Linux 7.3.1、Niri 26.04、Rust 1.98.1、GPUI 0.2.2。Release 构建，Midnight、串行软件渲染、CRT 关闭、静音，显示缩放 150%。固定可见且聚焦的 1280×900 逻辑像素窗口，优化前后交替运行，中英文各重复三次；表中为中位数。基线为 `719bcbf`。每次跳过首份启动转储，比较随后两份约间隔 5 秒的快照；所有受控采样点都核对了窗口尺寸和焦点。

**采样时存活的 CPU 堆内存**（KiB，不含字体文件映射）：

| 归因 | 英文优化前 | 英文优化后 | 中文优化前 | 中文优化后 |
| --- | ---: | ---: | ---: | ---: |
| SVG | 0.59 | 0.59 | 0.59 | 0.59 |
| 字体与文本 | 1,200.49 | 858.11 | 1,698.16 | 1,354.58 |
| 布局与元素 | 1,951.93 | 2,186.37 | 1,833.15 | 2,089.98 |
| 共享图集/场景缓冲 | 1,020.73 | 1,054.68 | 739.38 | 739.48 |
| 其他 | 19,512.58 | 19,512.89 | 19,737.91 | 19,738.21 |

布局/元素快照会因采到绘制的不同阶段而波动。例如英文优化前为 1,833–1,977 KiB，优化后为 2,090–2,202 KiB。侧栏复用会保留部分元素状态，**布局存活内存有所增加**；字体/文本存活堆约减少 342–344 KiB。不能把分配率降幅当作常驻内存降幅。

**预热后的累计分配率**（MiB/s，已除以每次实际转储间隔）：

| 路径 | 英文优化前 → 后 | 下降 | 中文优化前 → 后 | 下降 |
| --- | ---: | ---: | ---: | ---: |
| SVG | 0 → 0 | 无需优化 | 0 → 0 | 无需优化 |
| 字体与文本 | 15.317 → 1.532 | 90.0% | 17.074 → 1.528 | 91.1% |
| 布局与元素 | 127.870 → 113.501 | 11.2% | 138.972 → 124.706 | 10.3% |
| 全进程合计 | 191.686 → 163.551 | 14.7% | 203.328 → 173.615 | 14.6% |

重复字体错误的分配从英文约 188,163 次/s、中文约 213,144 次/s 降到 **0**。全进程分配次数从英文约 457,320 → 238,018 次/s、中文约 504,527 → 260,522 次/s。SVG 只在预热中发生解析/栅格化，稳定区间没有新增分配；这里的 0 不意味着 SVG 不占图集或 GPU 内存。

**默认分配器的进程 RSS**（独立运行，不注入分析器，MiB）：

| 语言 | 优化前中位数（范围） | 优化后中位数（范围） |
| --- | ---: | ---: |
| English | 88.15（87.89–88.40） | 88.46（88.15–88.74） |
| 简体中文 | 93.33（93.18–93.39） | 93.06（92.99–93.10） |

RSS 基本持平，没有证据支持明显的进程常驻内存下降。本次已验证的主要收益是更少的分配、释放和布局工作。

字体文件映射在两版中一致：英文虚拟映射 1,752 KiB，中文 20,784 KiB；英文实际字体 RSS 在 784–840 KiB，中文在 5,632–5,672 KiB。中文差异主要来自 CJK 字体映射，不能把约 20 MiB 的映射大小全部算成独占常驻内存。PSS 更低，随其他进程共享情况变化；逐次值见数据文件。

[逐次测量数据](benchmarks/ui-memory-2026-11-12.json) 保留字节数、分配次数、间隔和二进制摘要。早期未固定窗口的探索性数据中有一次绘制量异常偏低，未纳入以上统计。以上是带分析器的合成 UI 工作负载，不是游戏 FPS 或延迟提升声明。

## 实施的修改

### 字体：复用成功解析的请求

GPUI 0.2.2 会缓存字体查找失败，但读取错误缓存时会重新构造错误对象与文本。在本机，`sans-serif` / `monospace` 不是实际字体家族名称，反复查询会重复经过失败的候选项。

`src/desktop/fonts.rs` 为窗口保留五个惰性槽位：正文、medium、semibold、bold、调试器等宽字体。第一次仍使用原来的请求和 GPUI 回退规则，随后复用成功解析的完整 `Font`。没有硬编码替代字体，也没有只保留字体家族而丢失回退后的字重。回归测试验证原始请求与复用请求得到相同 `FontId`。

调试字体只在调试器需要时解析；无通知、无设置面板的纯画面全屏也不提前解析正文。系统字体数据库的建立仍由 GPUI 管理，没有修改依赖源码或额外加载一份字体库。

### 布局：只复用静态侧栏

整个控制台仍需要更新视频、运行状态和会话数据；没有缓存整个页面。侧栏使用 GPUI 自带的视图缓存，视频帧通知不再反复构建该区域的元素和布局。

语言、配色、当前页面和设置面板状态由订阅在绘制前比较，变化时通知侧栏；紧凑模式与缓存容器使用同一个宽度判断。边界、继承文字样式以及交互刷新继续由 GPUI 的缓存机制处理。侧栏用弱引用访问主视图，避免引用循环。

缓存只保存一个侧栏视图，不按帧、主题或语言累计条目。测试覆盖连续视频更新时的复用、语言/主题/页面/设置变化后的失效，以及 1250/1251 px 边界和既有键盘导航。为保持声明式构建函数清晰，控制台标题区和 CRT 选择器拆成了局部辅助函数。

### SVG：保留已有的按需路径

16 个 SVG 源文件共 **3,619 字节**，通过 `include_bytes!` 和 `Cow::Borrowed` 借用，没有每次加载复制字节。GPUI 已按路径、尺寸缓存栅格化结果，SVG 字体库也只在 SVG 文本需要时加载；当前图标不含文本。稳定测量区间没有新的 SVG 栅格化分配，因此没有添加重复缓存或预加载。

## 复现

需要 Linux、已有桌面会话、gperftools 的 `libtcmalloc`、LLVM 的 `llvm-symbolizer` 和 Python 3.11+。脚本不会安装工具。`--niri` 是可选的 Niri 控制器，只调整本次子进程创建的窗口；其他桌面环境请手动保持窗口可见、尺寸一致且不操作窗口。

```bash
cargo build --locked --release
cp target/release/eidoryn /tmp/eidoryn-measured

python3 scripts/profile_ui_memory.py capture \
  --binary /tmp/eidoryn-measured --output /tmp/eidoryn-heap-en \
  --language en --niri

python3 scripts/profile_ui_memory.py report /tmp/eidoryn-heap-en/end.heap \
  --base /tmp/eidoryn-heap-en/start.heap --binary /tmp/eidoryn-measured \
  > /tmp/eidoryn-heap-en/report.json

python3 scripts/profile_ui_memory.py capture \
  --binary /tmp/eidoryn-measured --output /tmp/eidoryn-rss-en \
  --language en --niri --rss-only

python3 -m unittest discover -s scripts -p 'test_profile_ui_memory.py'
```

每次使用新输出目录；中文用 `--language zh-CN`，其他视图可用 `--view game` 或 `--view fullscreen`。定时转储跳过首份启动快照，保存 `start.heap`、`end.heap` 和 `capture.json`。信号转储曾出现未完成的情况，因此脚本不使用信号打断分配器。堆分析会扰动时序，比较时保持工具、窗口、字体、语言和工作负载一致，至少重复三次。比较两个代码版本时分别保留二进制；不要对旧快照使用重新构建后的程序做符号解析。

## 保留与后续方向

- 保留 SVG 图集缓存、GPUI 的字形/文本缓存、游戏帧缓冲和必要的共享引用。没有为节省一次分配而加入全局锁、额外线程或 `unsafe`。
- 侧栏缓存用少量持久状态换取更少的逐帧工作，不能宣称为同等比例的 RSS 降幅。其余动态区域仍有布局临时分配；进一步分割视图需要额外的失效规则，应逐块测量收益再决定。
- Logo PNG、模拟器 RAM/VRAM、帧转换、音频和图形驱动都在“其他”或共享部分，不能归为 SVG。当前没有修改 Logo 分辨率或改动游戏显示质量。
- 未验证 Windows/macOS 的运行时内存数据；Linux 的结果受已安装字体、显示缩放、驱动、分配器和窗口状态影响。
