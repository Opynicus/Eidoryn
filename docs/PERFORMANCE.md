# 性能与代码审查

环境：Linux / Rust 1.98.1，release 构建；物理 GPU 为 AMD Radeon 780M / RADV。以下为有限样本的本地测量，不保证所有设备或场景的收益。发布材料只包含汇总性能数据和原创基准方法，不含游戏实际测试素材。

## 本次修改

| 模块 | 问题与改动 | 边界 / 权衡 |
| --- | --- | --- |
| `desktop` | 原来的相对 16 ms 轮询加上 UI 工作可能超过一个 NTSC 视频帧；改为 8 ms 固定截止时间，过期时跳过积压；按键仅在有新状态提示时立即重绘 | 轮询频率增加；保留像素复用与静态画面重绘节流 |
| `runner/worker` | 替换快照后在锁外释放旧对象，避免大像素缓冲析构延长互斥锁占用 | 通道语义不变，未测得独立锁等待收益 |
| `xa` / `cd_audio` | 解码结果直接送入既有有界队列，消除每包临时 PCM 向量与复制 | 最大格式每包消除 37,632 字节临时 PCM 分配；队列溢出策略和滤波状态不变 |
| `mdec` | 8×8 块打包使用 192 字节栈数组，按像素深度选择有效区间 | 保留四种输出深度、排序和符号语义 |
| `bus/dma` | 保留并清空已访问节点集合，复用链表遍历容量；将 DMA 实现移到子模块 | 保留循环检测、节点/字数上限及 RAM 回绕；会保留有界集合容量，不能宣称常驻内存一定下降 |
| `media` / `machine` | BIOS 校验共享有界文件读取；避免为了读固件构造整台机器，普通引导避免第二份固件复制 | 保留错误优先级、公共加载 API 和快速引导路径 |
| `cdrom` | 在 XA 音频分支返回前更新当前扇区头，避免查询位置得到过时的数据扇区地址 | 自主构造 Pause/Resume、过滤 XA 和后续 DMA 数据读取回归，不修改客体程序 |

没有新增依赖或 unsafe。原有 JIT 的可执行内存边界仍隔离于 `crates/jit-runtime`；主核心禁止 unsafe。库名继续保留 `eidoryn_psx` 以维持调用兼容，程序与 Cargo 包统一为 `eidoryn`，UI 名称为 Eidoryn。

## 原创 DMA / MDEC 微基准

相同编译配置，测试前后分别运行五轮，期间没有编译、GPU 测试或其他运行中的模拟会话。以每组耗时中位数比较：

| 负载 | 修改前 | 修改后 | 结论 |
| --- | --- | --- | --- |
| 10,000 条 × 1,024 节点 DMA 链 | 246.651 ms | 126.694 ms | 耗时减少约 48.6%，约 1.95× 吞吐 |
| 20,000 个 MDEC 宏块 | 93.660 ms | 94.519 ms | 未测得速度收益，约 0.9% 波动 |

各轮 DMA 命令计数均为 10,240,000，MDEC 校验和均为 `001e54b4b4966000`。长 NOP 链专门放大集合分配成本，并不代表典型绘图负载；MDEC 的分配减少也没有转化为该样本的速度提升。

## 整机与窗口测量

软件串行后端、相同检查点，三轮各 360 帧。时间包含核心执行与扫描输出，不含宿主限速。按键输入每 30 帧保持两帧。

| 工作负载 | 修改前每轮均值 ms | 修改后每轮均值 ms |
| --- | --- | --- |
| 无按键 | 13.691 / 13.769 / 13.602 | 13.682 / 13.980 / 13.836 |
| 重复按键 | 13.633 / 13.651 / 13.659 | 13.820 / 13.734 / 13.723 |

**未测得整体核心加速**，变化落在这次测量的波动范围，不能把减少分配换算为 FPS 增长。修改前后共 2,160 帧的 PC、步数、GPU/CD/SPU 计数、RGB 与 PCM 哈希逐行一致。未进行完整 RSS 或分配器 profiler 测量，分配减少量来自代码路径分析。

真实 GPUI 窗口连续运行 20 秒、每半秒重复按键，分析第 2–19 秒：旧轮询接收 1,012 次快照，帧号缺口 5；新轮询接收 1,021 次，帧号缺口 0。最大接收间隔从 32.455 ms 降至 24.141 ms；相同帧号的重复 render 调用从 6 次降至 0 次。核心都约 59.8 FPS。这只说明该样本中的 UI 快照丢失改善，不是显示器逐帧呈现证明，也不表示所有动作停顿均来自宿主。

## 既有后端基准

- 原创 32 层精灵绘图负载：串行 4.357 ms，多线程 4.456 ms，Vulkan 0.913 ms，包含扫描输出和读回。约 4.77× 是这项绘图基准的比值，整机对照曾为 −3.1% 至 +1.0%。
- 原创 64 条整数 ALU 循环、3,000 万 step：解释器 0.838 s，JIT 0.538 s，约 1.56×。普通工作负载的 JIT 覆盖率约 2.2%，未测得整体收益。
- 软件多线程不是默认更快；同步、队列和扫描输出成本可能超过并行收益。默认仍为串行软件 GPU 与解释器，Vulkan / 多线程 / JIT 均可手动切换。

## 后续方向

优先测量 Vulkan 到 GPUI 的显存读回/再次上传成本与呈现时间，再决定是否引入共享图像；检查同步光盘读取和记忆卡 fsync 的长尾；扩大设备时序、音频与实机一致性验证。JIT 扩展必须先证明中断、异常、延迟槽和代码失效行为一致。不以修改客体行为或移除边界检查换取速度。

## 最终验证

2026-11-10：`cargo fmt --all --check`、严格 Clippy（工作区 / 全目标 / 全特性）和 release 构建通过。工作区 169 项测试通过，5 项 GPU 测试默认忽略；无默认特性 154 项通过；另行运行物理 Vulkan 测试，5 项全部通过。Clippy 无项目代码警告，传递依赖 `proc-macro-error2 2.0.1` 仍有 future-incompatibility 提示。

原创光盘端到端程序再次运行 400,000 条指令，PPM 与历史 SHA-256 一致。已打开原生 GPUI 窗口确认 Eidoryn 名称及嵌入图标显示正常。

## 代码级微优化（模块拆分后）

结构拆分单独提交为 `8f90b49`，以下是其后的局部优化；不改变公共 API、设备时序、文件格式或错误处理结果。新基准 `examples/cd_bench.rs` 只生成原创临时扇区，退出时清理，无需 BIOS 或游戏。

| 路径 | 改动 | 分配 / 复制影响 |
| --- | --- | --- |
| `crates/ps1/src/cdrom.rs` | 即时响应使用借用的栈数组，清空并复用响应 FIFO；GetlocP 用固定 8 字节数组 | 消除即时响应的临时 Vec 和反复替换 FIFO 的分配；延迟响应继续拥有数据 |
| 同上 | 数据扇区缓冲保留容量，按切片填充并 drain 到数据 FIFO | 稳定运行后不再每扇区创建 2,048 / 2,340 字节 Vec；初始化与模式切换保持清空、背压和读取次序 |
| `crates/ps1/src/gpu/vulkan/mod.rs` | 映射期间直接转换成最终 RGB / u16 缓冲 | 消除中间 Vec<u32>；512×240 显示每次少一份 491,520 字节临时缓冲，完整显存读回少一份 2 MiB 临时缓冲，也不再先解包 u32 再重新转回 RGB 字节 |
| `crates/ps1/src/disc.rs` | 将每字节 8 次 EDC 位运算替换为编译期生成的查表 | 增加 1 KiB 只读表，无初始化锁、运行时分配或外部依赖；保留原位运算作为测试参照 |

上述分配大小是由数据结构和代码路径确定的消除量，不是分配器 profiler 或进程 RSS 测量。CD 缓冲会保留少量容量以减少分配，不能据此宣称空闲常驻内存一定更低。Vulkan 仍需驱动映射、最终输出缓冲和同步，未实现零拷贝呈现。

相同 release 配置，以重构后的提交为基线，同一份原创基准分别编译前后版本，五轮中位数：

| 原创负载 | 修改前 | 修改后 | 结论 |
| --- | --- | --- | --- |
| 1,000,000 个 Getstat 命令 | 18.645 ms | 18.846 ms | 未测得速度收益；主要减少分配 |
| 8,192 个 raw 数据扇区经 FIFO 读取 | 30.281 ms | 30.344 ms | 无明显速度变化，字节校验和一致 |
| 8,192 个 cooked ISO 扇区读取及 EDC 合成 | 118.676 ms | 35.837 ms | 耗时降低约 69.8%，约 3.31× 吞吐；EDC 总和一致 |

Vulkan 原创绘图基准第一组中位数为 0.963 → 0.868 ms/帧，重复测量为 0.855 → 0.858 ms/帧，完整显存均一致。**不据此宣称 Vulkan 稳定加速**，只确认移除了中间分配与复制。上述结果不是实际游戏 FPS 测量；尤其 raw BIN 不走 cooked ISO 的 EDC 合成路径。

机器重置/检查点的独立副本、跨线程快照的 String/CPU 数据、共享不可变像素的 Arc、延迟 CD 响应和最终图像缓冲均保留。没有引入 unsafe 或复杂生命周期参数；映射转换使用一个私有、静态分发的 FnOnce 回调，借用不离开映射作用域。

新增 CD 回归覆盖长短扇区切换、未读 FIFO 下预取、BFRD 背压、Init 丢弃旧扇区和再次读取；同一测试在修改前也通过，确保是既有行为约束。EDC 与原位运算比较全部单字节输入、零/全一及伪随机多种长度扇区。已有 Vulkan 测试继续覆盖 RGB15/RGB24、显存回绕、反馈和后端切换。

最终验证：格式检查、工作区全目标/全特性严格 Clippy、release 构建通过；工作区 173 项通过（另 5 项 GPU 测试默认忽略），应用无默认特性 143 项通过；另行运行的物理 Vulkan 测试 5 项全部通过。原创光盘程序的 400,000 指令输出 PPM 与之前的 SHA-256 完全一致。传递依赖 `proc-macro-error2 2.0.1` 的 future-incompatibility 提示仍存在。

## CPU / 设备周期模型的影响

2026-11-11，在相同 Linux x86-64 设备、release 构建和软件串行绘图下，用相近的本地工作负载分别测量三轮、每轮 180 个模拟视频帧，重复发送相同的按键脉冲：

| 指标 | 原单步一周期模型 | 新周期模型 |
| --- | --- | --- |
| 三轮平均帧耗时 | 14.767 / 14.815 / 14.807 ms | 11.282 / 11.177 / 11.240 ms |
| 单帧最长耗时 | 16.182 ms | 14.499 ms |
| 平均每帧执行 CPU 步数 | 566,222 | 271,778 |
| 三轮超过 16.72 ms 的帧 | 0 / 0 / 0 | 0 / 0 / 0 |

**这不是等量工作对比，也不能据此宣称模拟器执行效率提高。** 周期估算改变了每帧运行的 CPU 步数，两次测量的客体状态和设备事件也不能逐帧相等。结果只描述此样本的宿主耗时，不保证实时显示、系统音频或其他场景都能达到 60 FPS。准确性限制和专项回归见[周期模型](TIMING.md)。

| 固定工作量 | 基线 | 事件边界 | 耗时变化 |
| --- | ---: | ---: | ---: |
| 总线 7,770,000 周期，每次推进 1 周期 | 95.937 ms | 83.536 ms | -12.9% |
| 总线 7,770,000 周期，每次推进 7 周期 | 93.453 ms | 75.805 ms | -18.9% |

两版的周期数、帧数、GPU 状态、计时器和采样计数等基准检查点相同。该测试为原创的无光盘、空闲 DMA/SIO 合成负载，并非游戏帧率测试；活动 DMA、音频和其他工作负载可能呈现不同结果。

## UI 调试快照开销

2026-11-11，在 AMD Ryzen 9 8945H、Linux x86-64、Rust 1.98.1 上运行：

```bash
cargo run --locked --release --no-default-features --example snapshot_bench
```

使用原创演示的入口指令和已完成的帧缓冲，每项先预热 2,000 次，再测量 5 轮，每轮 100,000 次。`black_box` 保留结果，包含临时对象的析构。该快照没有挂载光盘或文件记忆卡。

| 操作 | 中位数 | 最小 / 最大 |
| --- | ---: | ---: |
| `Snapshot::capture()` 全部工作 | 0.594 µs | 0.592 / 0.596 µs |
| 复制 CPU 状态（608 字节） | 0.010 µs | 0.010 / 0.010 µs |
| 生成 9 条反汇编记录 | 0.529 µs | 0.521 / 0.533 µs |

反汇编占此合成快照的大部分耗时，但绝对开销不足 1 µs；按每秒 60 次计算约 32 µs/s。当前保留统一快照，没有新增 Worker/UI 按需通信。此结果不包含 GPU 读回等待、UI 绘制或实际游戏负载，也不是优化前后对比或帧率提升声明。后续只有在真实负载的 profiling 显示快照成为瓶颈时，再考虑按需生成或复用反汇编文本。
