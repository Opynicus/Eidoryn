# 游戏库刮削与恢复验收

本轮基于 `9fc73ae`，使用 CachyOS Linux x86-64、Ryzen 9 8945H 和 Rust 1.100.0 的 debug 构建。基准在临时用户目录运行。发行资料的真实网络验收使用美版《古惑狼》盘号 `SCUS-94900`。

## 运行与存储

- 扫描 CUE/BIN、ISO 和 CHD 时先保存本地游戏、盘片和路径。开启自动刮削时，同一事务也保存发行资料和封面任务。重复扫描复用路径及大小、修改时间和轻量指纹。手工确认的盘组和库内迁移保留内部 ID。PS1 是本版支持的平台。
- 首窗绘制和模拟器启动无需等待数据库迁移。后台线程共享一个 Tokio I/O runtime。SQLx SQLite 连接池负责新版迁移、显式入队、取消和恢复查询。已有扫描、游玩会话，以及需要把元数据和任务结果放进同一事务的代码沿用 rusqlite。数据库使用 WAL、外键和 10 秒 busy timeout。SQLx 静态检查使用仓库中的 `.sqlx/` 查询描述。
- 后台按序列号、平台和地区匹配 Wikidata。标题或别名相似度达到 75% 时，手工搜索最多提供八个模糊候选，由用户选定。字段覆盖优先于自动资料。Wikidata 的结构化数据以 CC0 发布，封面从所选服务下载到用户目录。[Wikidata 数据许可](https://www.wikidata.org/wiki/Wikidata:Licensing) · [Libretro 封面来源](https://github.com/libretro-thumbnails/libretro-thumbnails)
- 资料与封面的默认并发分别为 6 和 3，各自可设为 1–20，已保存的用户值继续生效。服务还有独立的请求和速率限制。429 遵守服务端的重试时间，超时和临时故障带抖动退避，任务最多尝试五次。永久错误可在修正配置后手工重试。[Wikidata 查询限制](https://www.mediawiki.org/wiki/Wikidata_Query_Service/User_Manual#Query_limits) · [IGDB 请求限制](https://api-docs.igdb.com/#rate-limits)
- 待处理任务在 SQLite 中，工作线程和写入结果通道有界。资料及任务状态同事务提交。封面在事务外写临时文件、验证图片，在短事务内发布文件引用与租约结果。手工取消后旧租约不能提交。正常关闭会归还任务，异常退出后可回收 120 秒的运行租约。失败记录含任务 ID、来源、阶段、错误类别与尝试次数。
- 发行资料响应上限 1 MiB，单张封面上限 8 MiB 和 16 百万像素。最多同时解码两张原图，每个解码器分配预算 128 MiB。256 像素缩略图使用有界的 64 项 GPUI 缓存。按内容哈希共享同一套原图和缩略图。启动时检查孤儿目录，临时下载保留至少 24 小时。
- `sessions` 是时长的单一事实来源。首次向前运行开始记录，按 30 秒及运行状态切换写绝对累计值。正常结束记录结束时间。进程异常退出后按照最后一次已提交的时间关闭会话；操作系统文件锁区分仍在运行的实例。历史记录缺少的开始时间保留为空。

## 迁移与回滚

从已有 v1–v4 库升级前，应用在同一目录以 `VACUUM INTO` 生成一致的 `library.sqlite3.vN.bak`，包含已提交的 WAL 内容。该名称对应最近一次从 vN 升级前的快照，更早的同名文件保存在带 UUID 的 `library.sqlite3.vN.<UUID>.bak`。同一数据库的多个进程串行执行迁移。v4 增加来源、索引及旧 URL 脱敏，v5 增加可恢复队列、封面属性、会话生命周期和平台字段。`game_works`、`game_files`、`metadata_sources`、`play_sessions` 可用于核对数据。备份存在期间，旧版本使用的封面目录会被保留。

同盘号的不同条目可以保留各自确认的发行版本。每条来源记录关联当时的原始响应及获取时间。最后一个条目切换版本后会回收旧响应。升级旧库时，只有能够核对到对应发行版的资料才关联历史响应。

如需回滚，先退出使用此库的所有 Eidoryn 实例，将当前数据库及同名 `-wal`、`-shm` 文件一起移入一个备份目录，再将匹配旧程序版本的 `.vN.bak` **复制**为原路径的 `library.sqlite3`。保留原用户目录的 `covers/`。回滚恢复到备份生成时的状态，较新的库文件仍能用于恢复升级后的改动。迁移快照保留旧库的原始内容，包括旧版本曾保存的自定义来源地址。全新用户库直接建为 v5。

## 本地基准

每个规模使用独立进程和空库。每个 ISO 为 10 KiB 的可区分测试数据。冷扫描和再次扫描分别遍历同一目录。暖刮削为每个游戏执行发行资料和封面两个阶段，所有输入都已在本地缓存。基准刻意隔离外部服务延迟，表中的失败数为任务失败数。真实网络的抽查独立进行。

2,000 项测试中，更新 1、16、32、64 个字段的独立 SQLite 事务 p95 分别是 14、41、71、144 µs。实际写入每批上限 32 项，最多合并 300 µs。默认配置的实测单批峰值为 9 项。调度器用部分索引读取已就绪工作，扫描器按规范化路径使用活动位置唯一索引。各目录先索引完整镜像，之后再遍历子目录。BIN 在临时索引中延期核对跨目录 CUE 引用，每次取 128 条。

为每个规模各启动 20 个新进程，打开已有游戏库并读取首份游戏列表。操作系统文件缓存保持温热，计时包含子进程启动和退出。100、500、2,000 项的 p50/p95 分别为 6.7/7.8 ms、11.0/11.8 ms 和 26.9/28.6 ms。

### GPUI 封面与滚动

## 复现

普通构建使用随代码提交的 SQLx 查询描述，可用 `SQLX_OFFLINE=true cargo check --locked --offline --all-features` 验证。修改静态队列 SQL 后，可从仓库根目录用临时 SQLite 库重新生成查询描述。

```sh
schema_dir=$(mktemp -d)
sqlite3 "$schema_dir/schema.db" < src/library/schema.sql
sqlite3 "$schema_dir/schema.db" < src/library/jobs/schema.sql
SQLX_OFFLINE_DIR="$PWD/.sqlx" DATABASE_URL="sqlite://$schema_dir/schema.db" cargo check --locked --features desktop
```

以下命令运行本地性能、恢复及来源验收。

```sh
for n in 100 500 2000; do
  EIDORYN_BENCH_GAMES=$n cargo test --locked --all-features --test library_scaling -- --ignored --nocapture --test-threads=1
  EIDORYN_BENCH_GAMES=$n cargo test --locked --all-features --bin eidoryn library_grid_virtualizes -- --nocapture --test-threads=1
done
cargo test --locked --all-features --lib library::jobs
cargo test --locked --all-features --lib artwork_recovers_from_crashes
cargo test --locked --all-features --lib runner::playtime
cargo test --locked --all-features --lib mock_wikidata_errors_and_cancellation -- --ignored
cargo test --locked --all-features --lib live_library_batch_full_and_incremental_smoke -- --ignored
```

子进程恢复用例分别在临时封面写完、发布后但事务未提交、以及事务提交后直接退出。另有进程在元数据与任务事务内及提交后退出，以检查恢复时两者一致。模拟 HTTP 覆盖超时、429、5xx、404、无效 JSON、字段缺失和传输中取消。两个连接切换封面来源的用例还验证，早先来源的慢请求无法在新来源发布后覆写文件或引用。

真实联网用例用一个新库依次对同一游戏执行全量、增量、全量，耗时 22.90 秒。各轮分别完成 3、0、2 个 HTTP 请求，Wikidata 与 Libretro 合计失败 0/5。这里以传输成功、完整读到限额内的 2xx 响应计为成功。缓存命中、发送前取消及客户端自动重定向的中间响应不计入请求数。SQLite 暖缓存基准的三个规模均没有外部请求。
